## 3. Phase 1: One-Time Infrastructure Bootstrap (Cloud Shell)

Execute this once inside [Google Cloud Shell](https://shell.cloud.google.com/?project=ai-learning-513415). Cloud Shell already has Google Cloud SDK, Terraform, Git, and GitHub CLI pre-authenticated.

```bash
#!/usr/bin/env bash
set -euo pipefail

PROJECT_ID="ai-learning-513415"
REPO="ashishisme/AI-Learning-Mod"
OAUTH_CLIENT_SECRET="<YOUR_GOOGLE_OAUTH_CLIENT_SECRET>"

echo "==> 1. Cloning repository..."
git clone -b cloud-beta https://github.com/ashishisme/AI-Learning-Mod.git
cd AI-Learning-Mod/deploy/terraform

echo "==> 2. Creating terraform.tfvars..."
cat << 'EOF' > terraform.tfvars
project_id         = "ai-learning-513415"
region             = "asia-south1"
service_name       = "ai-foundations-coach"
github_repository  = "ashishisme/AI-Learning-Mod"

billing_account    = "0168EA-9F583A-BC8B44"
monthly_budget_usd = 30
owner_alert_email  = "qunityfy@gmail.com"

oidc_issuer        = "https://accounts.google.com"
oidc_client_id     = "<YOUR_GOOGLE_OAUTH_CLIENT_ID>"
admin_emails       = "qunityfy@gmail.com"
backup_retention   = "1209600s"
EOF

echo "==> 3. Initializing and Applying Terraform..."
terraform init
terraform apply -auto-approve

echo "==> 4. Populating Secrets in Secret Manager..."
# Upload randomly generated 32-byte session secret
head -c 32 /dev/urandom | base64 | tr -d '\n' | gcloud secrets versions add ai-foundations-coach-session-secret \
  --project="${PROJECT_ID}" \
  --data-file=-

# Upload OAuth client secret securely
printf "%s" "${OAUTH_CLIENT_SECRET}" | gcloud secrets versions add ai-foundations-coach-oidc-client-secret \
  --project="${PROJECT_ID}" \
  --data-file=-

echo "==> 5. Configuring GitHub Environments & Variables..."
WIF_PROVIDER=$(terraform output -raw github_variables | grep GCP_WORKLOAD_IDENTITY_PROVIDER | awk -F'"' '{print $4}')
DEPLOY_SA=$(terraform output -raw github_variables | grep GCP_DEPLOY_SERVICE_ACCOUNT | awk -F'"' '{print $4}')

if command -v gh &> /dev/null; then
  gh repo set-default "${REPO}" || true
  
  # Set repository-level deployment gate
  gh variable set CLOUD_DEPLOYMENT_READY --body "true" --repo "${REPO}"
  
  # Configure staging and staging-promote environments
  for ENV in "staging" "staging-promote"; do
    gh api -X PUT "repos/${REPO}/environments/${ENV}" || true
    gh variable set GCP_WORKLOAD_IDENTITY_PROVIDER --env "${ENV}" --body "${WIF_PROVIDER}" --repo "${REPO}"
    gh variable set GCP_DEPLOY_SERVICE_ACCOUNT --env "${ENV}" --body "${DEPLOY_SA}" --repo "${REPO}"
    gh variable set GCP_PROJECT_ID --env "${ENV}" --body "${PROJECT_ID}" --repo "${REPO}"
    gh variable set GCP_REGION --env "${ENV}" --body "asia-south1" --repo "${REPO}"
    gh variable set GCP_ARTIFACT_REPOSITORY --env "${ENV}" --body "ai-foundations-coach" --repo "${REPO}"
    gh variable set GCP_SERVICE --env "${ENV}" --body "ai-foundations-coach" --repo "${REPO}"
  done
  echo "GitHub environment variables configured successfully."
else
  echo "Manual step: copy variables from 'terraform output github_variables' to GitHub Repository Settings."
fi

echo "==> Infrastructure Bootstrap Complete."
```

## 5. Phase 3: Triggering Deployments (Tag-Driven GitOps)

Deployments are strictly tag-driven. When you tag a release on your local branch (e.g. `cloud-beta`), GitHub Actions checks out the exact commit associated with that tag and runs the deployment pipeline.

From your local machine terminal:

```bash
# 1. Switch to cloud-beta branch and verify working tree is clean
git checkout cloud-beta
git pull origin cloud-beta

# 2. Create release tag
git tag v0.1.0

# 3. Push release tag to GitHub
git push origin v0.1.0
```

## 6. Phase 4: Release Pipeline Execution & Promotion

1. Go to the **Actions** tab in GitHub:  
   `https://github.com/ashishisme/AI-Learning-Mod/actions`
2. Select the running **Cloud Run release** workflow.
3. The pipeline executes:
   - **Verification**: Go tests (`-race`), `govulncheck`, Vue build, Playwright end-to-end tests, Firestore emulator tests.
   - **Container Build**: Compiles multi-platform Docker images (`linux/amd64`, `linux/arm64`) with an attached SBOM and pushes to Artifact Registry.
   - **Candidate Deployment**: Deploys the revision to Cloud Run with `--no-traffic` and tag `rc-v0-1-0`.
   - **Candidate Smoke Test**: Executes `deploy/scripts/smoke.sh` against the tagged candidate URL.
4. **Promotion Approval**:
   - The workflow pauses at the `promote` job.
   - Click **Review deployments**.
   - Check **`staging-promote`** and click **Approve and deploy**.
5. Live traffic shifts 100% to the new revision, and the public health check runs.

## 8. Rollback Procedure (<2 Minutes)

If a production defect is identified:

1. Open GitHub Actions: `https://github.com/ashishisme/AI-Learning-Mod/actions`.
2. In the left sidebar, click **Roll back staging**.
3. Click **Run workflow**:
   - Branch: `cloud-beta`
   - Revision to send all traffic to: `<PREVIOUS_REVISION_NAME>` (e.g. `ai-foundations-coach-00001-abc`, found in the previous release summary).
4. Click **Run workflow**. Traffic will revert immediately without rebuilding containers.
